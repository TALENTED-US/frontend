# UI 변경에 따른 API 영향 공유

UI가 변경될 때 프론트엔드와 백엔드가 함께 확인해야 할 내용을 기록합니다.

## 작성 형식

| 항목 | 내용 |
| --- | --- |
| 화면·경로 | 변경되는 페이지 경로 |
| UI 변경 | 사용자 화면에서 달라진 내용 |
| 기존 API | 현재 호출하는 endpoint와 목적 |
| 필요한 데이터 | 화면 표시와 요청에 필요한 필드 |
| API 영향 | 없음 / 응답 변경 / 요청 변경 / 신규 API / API 제거 후보 |
| 백엔드 요청 | 백엔드 작업이 필요하면 구체적으로 작성 |
| 프론트 대응 | store, mapper, loading/error/empty 처리 변경 |

## 공유 전 확인 사항

- UI에서 새 값을 표시하면 응답 필드가 실제로 존재하는지 확인합니다.
- 입력 항목이 추가·삭제되면 create/update 요청 DTO와 validation 영향을 확인합니다.
- 화면에서 섹션이 사라져도 다른 계산이나 store가 같은 API를 사용하는지 확인한 뒤 호출 제거 여부를 결정합니다.
- enum, 상태값, 날짜 형식, 금액 단위가 변경되면 프론트 mapper와 백엔드 명세를 함께 갱신합니다.
- loading, error, empty 상태에 필요한 응답 규칙도 함께 공유합니다.

## 백엔드 공유용 결론

### 이번 개편으로 변경된 API 계약

- 없음
- 신규 endpoint 없음
- 삭제할 endpoint 없음
- 요청·응답 DTO 필드 변경 없음

### `/simulation/new`에서 계속 필요한 요청 데이터

| UI 데이터 | API 요청 필드 | 사용 endpoint |
| --- | --- | --- |
| 시작일 | `simulationStartDate` | `POST /simulation`, `PATCH /simulation/period` |
| 종료일 | `simulationDueDate` | `POST /simulation`, `PATCH /simulation/period` |

- 1·3·6·12개월 빠른 선택값 자체는 서버로 보내지 않습니다.
- 프론트에서 선택 개월 수를 종료일로 계산한 뒤 기존 두 날짜 필드만 전송합니다.
- 따라서 `durationMonths` 같은 신규 필드는 필요하지 않습니다.

### UI에서 제거됐지만 삭제하면 안 되는 데이터

| 데이터·API | 유지 이유 |
| --- | --- |
| 거래내역 조회 `getTransactionsApi()` | 현재 자산·월평균 수입·월평균 지출과 버티는 기간 계산에 사용 |
| `financialReport.totalAssets` | simulation store의 `totalAssets` 계산에 사용 |
| `financialReport.monthlyIncome` | 시뮬레이션 결과 계산에 사용 |
| `financialReport.monthlyExpense` | 현재 소진액과 버티는 기간 계산에 사용 |
| `GET /simulation/items/report` | 확정 및 항목 적용 이후 서버 계산 결과 동기화에 사용 |

`/simulation`에서 현재 재정 리포트 UI가 제거됐다는 이유로 위 API나 필드를 제거하면 시뮬레이션 계산과 확정 결과가 달라질 수 있습니다.

### UI 전용으로 추가·변경된 항목

- 배너 문구와 `10만원` 강조값: 현재 정적 UI 문구이며 API 데이터가 아닙니다.
- 위험·안정 버티 이미지: 로컬 정적 에셋이며 API 데이터가 아닙니다.
- 기간 빠른 선택 활성 상태: 프론트 로컬 상태이며 저장 대상이 아닙니다.
- 뒤로가기 버튼 디자인과 위치: API 영향 없음.

### 추후 백엔드 협의가 필요한 경우

배너의 `10만원`, 현재 위험 상태, 절약 후 안정 상태를 사용자별 실제 계산값으로 표시하려면 다음 데이터가 필요합니다.

- 추천 절약 금액
- 적용 전 예상 생존 기간과 위험 상태
- 추천 적용 후 예상 생존 기간과 위험 상태

현재 요구사항은 정적 안내 배너이므로 이번 작업 범위에서는 신규 API를 요청하지 않습니다.
